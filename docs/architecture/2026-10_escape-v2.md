Branch `semppi-v2/escape-fix` (from `paper/submission-audit`, head 0c95da2).
Written 2026-10-18. Design: `DESIGN_ADVICE.md` §2 with the decisions D-1 and D-3.
Evidence of the defects: `experiments/results_pilot_rerun/ROOT_CAUSE.md`.

## 2. Escape state table

`prev_entrapped_` is the detector state at the end of the previous cycle.
The escape path is decided at the start of a cycle, before the base call.

| State | Condition | Path that MPPI follows | Output of this cycle |
|---|---|---|---|
| idle | not entrapped, nothing substituted | BT path | stock MPPI, CBF as before |
| select | entrapped, nothing substituted | escape path (new) | hop 1 logged, path published |
| standing | entrapped, waypoint frozen | escape path | none |
| re-select | entrapped and one of: robot within `se_escape_reselect_radius` of the waypoint; `se_escape_reselect_period` over; no movement of `se_escape_stall_distance` in `se_escape_stall_time`; straight line to the waypoint blocked | escape path (new) | hop n+1 logged, path published |
| restore | not entrapped, substituted | BT path (latest) | empty path published |
| reset | `reset()` | BT path (latest), state cleared | empty path published |
| new task | `setPlan` for a new goal, or after an idle loop | the new BT path | state cleared |
| BT replan while substituted | `setPlan`, same goal | stays the escape path; the BT path is kept in the controller for progress and the near-goal test | none |
| SE layer off | `se_enabled` false | BT path (latest) | empty path published |

A waypoint that did not work (timeout, blocked, no movement) is remembered for the
episode, with the stall pose and the last `se_escape_avoid_hops` hop origins: no later
hop leads toward them.

## 3. Differences from the design advice (and why)

1. **Mouth ray.** From the mouth of a pocket the ray back into the pocket reaches
   the 3 m window edge, so it is a horizon ray and the closest to the goal bearing.
   Measured at the s1 mouth (-1.0, 0.0): the plain rule picks 0 degrees, into the
   pocket (`GapPocket.AtTheMouthTheRayBackToTheStallPoseIsExcluded`). The
   selection therefore excludes rays that lead to the pose where entrapment was
   declared (`se_escape_avoid_radius` 1.0 m), to recent hop origins and to failed
   waypoints (`se_escape_avoid_hop_radius` 0.6 m). Without the hop origins a
   rotated pocket gave a 2-cycle swing between two places.
2. **Movement watchdog** (`se_escape_stall_time` 3 s, `se_escape_stall_distance`
   0.15 m). On a development geometry MPPI stood still in front of a gap that the
   binary threshold (cost >= 253) called free but whose inflation cost was about
   160. The rule "after 15 s" is too slow for Nav2's 10 s progress checker.
3. **Gap test tolerance.** The advice expects the selection "within 10 degrees of
   180". The rule takes the horizon ray closest to the goal bearing; the mouth cone
   has 5 horizon rays (160 to -160 degrees at the 10 degree grid), so the choice is
   the cone edge, 20 degrees from the pocket axis (-160 degrees at the s1 stall pose).
4. **Humble.** Humble's MPPI throws `std::runtime_error("Optimizer fail to compute
   path")`; there is no `nav2_core::NoValidControl`. `no_valid_control.hpp` hides it.
   Not built here (the environment is Jazzy only).
5. **Test placement.** The new unit tests live in `test/deployment/`, because
   `scripts/check_paper_numbers.py` counts `test/test_*.cpp` against the paper's
   82 tests in 13 files. The paper must count them when its text changes.
6. **Option B** (an own command when all rollouts collide) is not implemented.
   Limitation: when the footprint is already inside the inflated band and every
   rollout collides, the optimizer throws, the detector now runs, and the escape
   path is handed to MPPI, but MPPI still cannot produce a command in that cycle.
   In the closed loop with `vx_min = -0.35` this never happened (0 throws in all runs).
   **The detector update on a throw cannot act under `failure_tolerance` 0.0.** With 0.0,
   `controller_server` rethrows `NoValidControl`; `computeControl` catches it and calls
   `publishZeroVelocity()`, which calls `reset()` on every controller, so the detector state is
   gone in the same cycle, and in the campaign configurations C3 and C4 the first throw ends the
   goal. The update acts only with `failure_tolerance` -1 (campaign 1). The closed-loop rig keeps
   going after a throw, as -1 would; therefore its pass rule requires `throws == 0`, and a run with a
   throw is reported as "C4 would abort".

7. **Additions beyond the advice, and the mirror.** The lead accepted these additions as the shipped
   algorithm on 2026-10-18 (decision E-1). They are disclosed in the pre-registration, and the paper
   must disclose them in the method section and in the limitations (section 6). Items 1 and 2 (and
   the 0.2 m floor on the waypoint distance, the 0.6 m minimum clearance of horizon candidates, and the
   list of at most 6 failed waypoints) are rules that `DESIGN_ADVICE.md` does not have. With the avoid radii at 0 and
   the stall time at 1e6 the headless test passes 19 of 56 geometries and fails the primary
   `w22_d13_r30_a10` in 3 of 3 runs (23 to 26 hops, closest approach 2.37 to 2.39 m); the shipped
   algorithm passes 56 of 56. The Python mirror now transcribes the shipped algorithm, behind the
   flag `escape_extras` (false is the design as advised), with the C++ progress chain and the one
   cycle of lag; `experiments/benchmark2d/tests/test_v2_cxx_parity.py` calls the C++ through
   `parity_shim` and compares selection, ray casting and the progress chain.
8. **The critic's log line.** The `EscapeCritic` line was "selected opening". It is a probe of the
   critic: no avoid list, no hysteresis, and its goal is `data.goal`, which is the escape waypoint
   while the path is substituted. It is now labelled "critic-side probe (... NOT the escape
   heading)". The controller's heading is the `SE escape waypoint N` line.
9. **Switching the SE layer off during an escape.** `computeVelocityCommands` returns before
   `updateEntrapment` when `se_enabled` is false, so nothing cleared the state. `manageEscapePath`
   now clears `prev_entrapped_`, the detector and the shared flag while the layer is off (a toggle
   is a task boundary for the escape); the test is
   `ControllerEscapePath.ToggleOffAndOnDuringAnEscapeClearsTheEntrapmentState`.

**Measured ablation of the additions (confirmation 2, 2026-10-18).** The whole development family
(56 valid geometries, one run each), one process per sweep. MPPI's noise cannot be seeded from the
test, so the sweeps are independent runs and each count is stated for its own sweep.

| Sweep | Additions | Passed of 56 |
|---|---|---|
| `on1` | on | 55 (the one non-pass, `w26_d11_r15_a6`, never entered the pocket and reached the goal) |
| `on2` | on | 56 |
| `on3` | on | 56 |
| `off1` | off | 16 |
| `off2` | off | 18 |
| `off3b` | off | 14 |

With the additions 167 of 168 runs pass; without them 48 of 168. No run had a contact or a
`NoValidControl` throw. Earlier sweeps: implementer 56 of 56 and 19 of 56, reviewer 55 of 56 (the
non-pass never entered the pocket) and 16 of 56. A sweep stalled twice, in either arm: in `off3` (additions off) and in `on1` (additions on, on
`w22_d11_r0_a10`, reproduced by the reviewer). Each time the run had finished and its row was complete; the main thread then
spun at 100 percent of one core in the rig's teardown (`Rig::~Rig`, `utrap_rig.hpp`, at `costmap_ros_.reset()` or `node_.reset()`;
the costmap was never activated or cleaned up) and ignored SIGINT. It is not a control-cycle event and the counts are not affected. Commit `b7e012a`; logs in
`/mnt/d/wsl/se-mppi/v2_confirm2/`.

**Second held-out pocket.** A pocket outside the development family (an L-shaped dead end, corridor
2.05 m deep against 1.85 m for the deepest development pocket, `s1_utrap` (0.20 m, 11 percent, more), with a closed bent leg) was specified by the lead,
authored blind, and added to campaign 2 as the pocket on which the claim of transfer rests. Its name
was not written outside `experiments/campaign2/` before the campaign. Since the campaign ended on
2026-10-22, `test_heldout_guard` scans the repository for both held-out names and allows them only in
`experiments/campaign2/`, `docs/papers/` and `scripts/check_paper_numbers.py`.

See the hand-back report of the implementation run (numbers, mutants, limits). The
raw logs are in `/mnt/d/wsl/se-mppi/escape-fix/`; those of the first review fixes are in
`/mnt/d/wsl/se-mppi/escape-fix/logs/review1/` (the ablation with the additions switched off, the
sweep with the zero-throw pass rule, the mutation results).

Mutation evidence of the review fixes (one mutant at a time on a copy of the tree, the covering tests
run; scripts `rv1_mutate.py` and `rv1_cxxmut.py` in the job directory, results in `review1/`):

- Python (campaign driver, provenance, analyzer, PREREG text, mirror): 112 mutants in the first
  run, 99 killed. The 13 survivors were examined. Two were equivalent (`delta >= pi/2` against `>`:
  at 90 degrees `sin` is 1, so the next test cannot differ; the `MIXED_ATTEMPTS` line of PREREG
