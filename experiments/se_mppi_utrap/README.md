# se_mppi_utrap

AMR Gazebo testbed. Generated by the `amr-gazebo-testbed` skill.

- **Target**: ROS 2 jazzy + Gazebo harmonic
- **World**: 8.0 × 8.0 m, 3 obstacle(s) + perimeter walls
- **Robot**: generic differential-drive AMR with 2D lidar + IMU

## Build

```bash
colcon build --packages-select se_mppi_utrap
source install/setup.bash
```

## Run

```bash
ros2 launch se_mppi_utrap testbed.launch.py
```

ROS 2 topics published / subscribed after launch:

| Topic           | Direction         | Type                        |
|-----------------|-------------------|-----------------------------|
| `/cmd_vel`      | sub (ROS → Gz)    | `geometry_msgs/Twist`       |
| `/odom`         | pub (Gz → ROS)    | `nav_msgs/Odometry`         |
| `/tf`           | pub (Gz → ROS)    | `tf2_msgs/TFMessage`        |
| `/joint_states` | pub (Gz → ROS)    | `sensor_msgs/JointState`    |
| `/scan`         | pub (Gz → ROS)    | `sensor_msgs/LaserScan`     |
| `/imu`          | pub (Gz → ROS)    | `sensor_msgs/Imu`           |
| `/clock`        | pub (Gz → ROS)    | `rosgraph_msgs/Clock`       |

## Verify the world loads (without ROS)

```bash
gz sim -r worlds/testbed.sdf --headless-rendering -s --iterations 200
```

If this fails, the SDF or plugin filenames are wrong for your Gazebo version. Re-check
`config/ros_gz_bridge.yaml` (`gz_type_name`) and `worlds/testbed.sdf` (`<plugin filename=...>`)
against your installed Gazebo.

## Drive the robot

```bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard
```
